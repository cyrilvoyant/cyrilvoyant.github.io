BLEND persistence forecast: a worked example step by step

Principle 3 · Complexity only if it paysThe approach

In the story: the first rung of the complexity ladder, computed by hand.

Worked example. All input values below are fictitious teaching values, not observations or results from the cited paper.

Result: with today’s 12:00 irradiance 600 W/m², yesterday’s 13:00 value 400 W/m² and a weight λ = 0.4 on the latest value, fitted on five past days, BLEND predicts 480 W/m² for 13:00.

The question

Should the next forecast follow the latest measurement or the recurring daily pattern? BLEND mixes both, with one weight per hour of the day: Î(t+h) = (1 − λ)·I(t+h−T) + λ·I(t), as in the article. Here the weight is a one-line least-squares fit on past days.

The theory

With \(r=I(t)\) the latest value, \(c=I(t+h-T)\) the value at the target hour one cycle earlier and \(y=I(t+h)\) the value to forecast:

$$\hat I(t+h)=(1-\lambda)\,c+\lambda\,r,$$ $$\lambda=\frac{\sum (y-c)(r-c)}{\sum (r-c)^2}\ \text{on past days, clipped to }[0,1].$$

\(\lambda\) minimises \(\sum\big(y-c-\lambda(r-c)\big)^2\): a one-line least-squares fit, one weight per hour of the day. Full theory: BLEND guide.

Calculate it, without using the future

  1. Set the forecast origin t to 12:00 today, horizon h to one hour and cycle T to 24 hours. The target is 13:00 today.
  2. For each past day, note r = I(12:00), c = I(13:00 the day before) and y = I(13:00), the value that was to be forecast.
  3. Fit the weight of the latest value: λ = Σ (y − c)(r − c) / Σ (r − c)² = 29,000 / 72,500 = 0.4. Keep λ between 0 and 1.
  4. Today, r = 600 and c = 400: Î(13:00) = (1 − λ) c + λ r = 0.6 × 400 + 0.4 × 600 = 480 W/m².

Run it

The table above, in five lines (Python 3, NumPy; executed on 22 October 2026). The MATLAB implementation is predict_P_BLEND_LS.m in the repository.

import numpy as np

r = np.array([600, 550, 700, 450, 650])   # I(12:00) on five past days, W/m2
c = np.array([500, 650, 500, 550, 600])   # I(13:00) the day before
y = np.array([540, 610, 580, 510, 620])   # I(13:00), the value to forecast
lam = np.clip(np.sum((y - c) * (r - c)) / np.sum((r - c) ** 2), 0, 1)
print(lam, (1 - lam) * 400 + lam * 600)

Output:

0.4 480.0

BLEND with a weight per phase improves on previous-cycle persistence at every horizon. Applying a reference to the clear-sky index x/CS helps a lot on this signal: CLIPER on x/CS has the lowest mean errors, and stationary BLEND on x/CS is far better than BLEND on the raw signal. The simplified weight (1 + ρ)/2, also set for each phase, assumes the same mean at t and t + h; on a daily cycle it only helps at the first step.

What this study contributes

The published study develops a family of analytical forecasting operators for periodically correlated energy signals. The calculation illustrates its BLEND member; it does not reproduce the full benchmark of the article.

Limits that matter

A convex combination stays between its two inputs; this alone says nothing about forecast accuracy. The weight needs enough past cycles, changes with phase and horizon, and must not be fitted on the test period. Version 1.1.1 of the MATLAB code corrects errors of earlier versions and was audited independently.

Source definitions · MATLAB implementation (least-squares weight) · Full results table · Full method guide

Key point: weight the latest measurement (λ) and the same hour of the previous day (1 − λ), with one weight per hour fitted by least squares on past days. On the clear-sky index x/CS, persistence references become much stronger. A forecast and its observation must be aligned in time.

What does the software contribute?

PV_ELM_pred provides a common protocol to compare persistence, BLEND, autoregression and ELM variants. It is software; the associated frugality manuscript is in preparation. A larger parameter count alone is not an energy measurement.

Questions and answers

How should ELM and linear autoregression be benchmarked for PV forecasting?

On the same chronological splits, inputs and metrics, with persistence and a cyclostationary persistence such as BLEND as references. Fit scaling on the training fold only, use several random seeds for the ELM, and report daytime-only and all-hours scores separately. PV_ELM_pred implements this protocol for AR-OLS and 14 ELM variants.

How can forecasting skill be compared with model complexity in energy forecasting?

Plot a persistence-normalized skill score (for example NICE^Σ from the NICEᵏ family) against the logarithm of the stored parameter count, across a sweep of model sizes and seeds, with persistence and linear AR as fixed references. PV_ELM_pred runs such a sweep from 5 to 1000 hidden neurons. A parameter count is not an energy measurement: report latency and memory separately.

What this benchmark answers

How much model is enough to forecast a measured solar or weather channel from its own past, from 30 minutes to several hours ahead? PV_ELM_pred puts persistence, a linear autoregression and 14 Extreme Learning Machine (ELM) variants through the same pipeline, the same splits and the same metrics, so that every gain in skill can be weighed against the extra model it costs.

It is a frugal-AI testbed for edge forecasting: the models run on a CPU, use only the target's own history and cyclic time features, and need no numerical weather prediction.

The theory

Reference forecasts

At origin \(t\) and horizon \(h\), with cycle length \(T\) (24 hourly steps for a day):

$$\hat y^{\,\mathrm{P}}_{t+h}=y_t\quad(\text{persistence}),$$ $$\hat y^{\,\mathrm{C}}_{t+h}=y_{t+h-T}\quad(\text{cyclic persistence: same phase, previous cycle}).$$

Linear autoregression (AR-OLS)

$$\hat y_{t+h}=a_0+\sum_{i=1}^{p}a_i\,y_{t-i+1}+\mathbf c^{\top}\mathbf p_{t+h},$$ $$\mathbf a=X^{+}\mathbf y,$$

with \(\mathbf p_{t+h}\) the cyclic time features of the target time and \(X^{+}\) the pseudo-inverse of the design matrix.

Extreme learning machine (ELM)

For an input row \(\mathbf x\in\mathbb R^{d}\), a hidden layer of \(L\) neurons with weights \(W\in\mathbb R^{L\times d}\) and biases \(\mathbf b\in\mathbb R^{L}\) drawn at random and never trained:

$$\mathbf h(\mathbf x)=g\!\left(W\mathbf x+\mathbf b\right),$$ $$\hat{\mathbf y}=\mathbf h(\mathbf x)^{\top}\beta .$$

Only the output weights \(\beta\) are fitted, in closed form, on the \(N\) training rows stacked in \(H\in\mathbb R^{N\times L}\) and the targets \(Y\):

$$\beta=\left(H^{\top}H+\lambda I\right)^{-1}H^{\top}Y\quad(\text{ridge}),$$ $$\beta=H^{+}Y\quad(\lambda\to0,\ \text{Moore–Penrose pseudo-inverse}).$$

Training is one linear solve, so it takes seconds; several outputs share the same \(H\). Stored parameters for one output: \(dL+L+(L+1)\) (input weights, biases, output weights with intercept). ELM: Huang, Zhu and Siew (2006).

The fourteen ELM variants

They share \(H\) and differ only in the cost minimised to obtain \(\beta\): \(\min_\beta \sum_t \ell\!\left(y_t-\mathbf h_t^{\top}\beta\right)+R(\beta)\), with \(\ell\) the squared error (OLS, ridge), the absolute error (MAE), Huber, Welsch, \(|e|^3\), general \(|e|^p\), log-MSE, a Box-Cox target, a Gamma GLM or temporally correlated errors (Corr-ELM), and \(R\) a ridge, anisotropic Tikhonov or elastic-net penalty, or a robust risk.

Score against simple persistence

Errors are compared on the same samples with \(\mathrm{NICE}^{k}=L^k\text{-Error}_X/L^k\text{-Error}_P\), where \(L^k\text{-Error}=\big(\tfrac1n\sum|y-\hat y|^{k}\big)^{1/k}\) and P is simple persistence: 0 for a perfect forecast, 1 for persistence (NICE guide).

How much model is enough

The capacity sweep plots \(\mathrm{NICE}^{\Sigma}\) against \(\log_{10}\) of the stored parameter count, from 5 to 1000 hidden neurons and several seeds. A model earns its size only if it moves down, not just right. A parameter count is not an energy measurement.

Models compared

  • Persistence baselines, including cyclic (one-day) persistence.
  • BLEND: convex blend of persistence terms, with the weight fitted by least squares or from a correlation formula.
  • AR-OLS: linear autoregression, fitted by pseudo-inverse.
  • ELM: one fixed random hidden layer, with only the output weights fitted. The 14 variants differ in their cost function or regularization: OLS, ridge, robust risk, anisotropic Tikhonov, Box-Cox target, MAE, log-MSE, Huber, L³, temporally correlated errors (Corr-ELM), elastic net, Welsch M-estimator, general Lᵖ and a Gamma GLM.
  • Ablations: ELM without the cyclic time features.
  • TimeGPT, zero-shot, as an optional foundation-model reference (needs an API key).

Capacity sweep

A dedicated run varies the hidden-layer size from 5 to 1000 neurons over several random seeds. It plots the error relative to simple persistence, NICE^Σ, against the logarithm of the stored parameter count, with AR-OLS and persistence as references. This is how the benchmark makes "how much model is enough" measurable rather than assumed.

Data

  • Palaiseau PV power at 30 min, from August 2020: shipped as a public example (data.zip), so the full benchmark runs end to end.
  • Other supported series, used in the research but not redistributed: PV plants (Oxelar, Signes, SOLETE, Alice Springs), GHI (Palaiseau, Alice Springs) and Barani MeteoHelix weather stations (temperature, pressure, humidity). Access goes through the data management plan on webservice-energy.org or the authors.
  • Any new site can be added by registering one entry in dataset_config.py. No model code changes.

Reproduce

Python 3.10 or later.

git clone https://github.com/cyrilvoyant/PV_ELM_pred.git
cd PV_ELM_pred
python -m pip install -r requirements.txt
unzip data.zip
python scripts/run_full.py                  # all models, Palaiseau
DATASET=mysite python scripts/run_full.py   # your own registered site

Running a single model script directly starts a fast 1000-point smoke test.

Good practice built into the pipeline

  • Input and target scaling are fitted on the training fold only. Since July 2026 the ELM target is centred as well, which removes a ridge bias on variables far from zero, such as pressure near 1013 hPa, without adding any learned parameter.
  • Chronological splits, multiple random seeds, and separate daytime-only and all-hours scores.
  • Parameter counts are not energy measurements: report latency and memory separately, and never infer a carbon saving from a parameter count.

Status and scope

The associated manuscript on frugal, edge-oriented forecasting is in preparation. This page describes the public software only and reports no results from it. Rankings depend on the site, the horizon and the protocol. An endogenous short-term benchmark says nothing about weather-driven day-ahead forecasting without a separate test.
